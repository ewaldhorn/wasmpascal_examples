# Host ABIs (wasmpascal-specific)

> Part of the WasmPascal in-browser **Pascal quick reference** (the `?` help overlay). Source: `webpascal/index.html`.

- **pascaldom** — exports `pascaldom_main`; self-wires its canvas + event loop via the `pascaldom_env` DOM/canvas imports. Reach it with **`uses WEB`**: the embedded unit declares the whole bridge, so your program writes no `external` block, picks no `CB_*` ids, keeps no `case id of` dispatcher and needs no `exports` clause — the program body *is* `pascaldom_main` — and handlers register by name with `web.On(h, 'mousedown', HandleDown)` / `web.OnTick(HandleTick)` (`web.Off(id)` retires one). Examples: `web_dom.pas` (the guided tour), `sweep.pas`, `paint.pas`, `musicbox.pas`, `colors.pas`. The raw bridge still works — declare your own `external`s and export the entry points yourself; `pascaldom_probe.pas` is the same job written both ways, for comparison.
- **batchiness** — exports `batchiness_main`; batched-canvas game + Web Audio SFX via `app_env`. Examples: `pascaloids.pas`, `pong.pas`, `transforms.pas`, `sparks.pas`, `growable.pas`, `flightleader.pas` (FLIGHT LEADER — a 6-unit arcade space-combat-style game), `xonix.pas` (Xonix — the fill floods from the balls, so it can never cover one), `floaty_car.pas` (Floaty Car — stay on the winding road; it only gets faster), `dugster.pas` (DUGSTER — a Digger-style dig-em-up in 5 units).
- **basic_canvas** — exports `wasm_init`/`wasm_update`/`wasm_click`/`wasm_get_pixels`/`wasm_get_width`/`wasm_get_height`, plus optional `wasm_pointer_down`/`wasm_pointer_move`/`wasm_pointer_up` for press-and-drag (mouse or touch); the host drives a fixed-step animation loop and blits the RGBA buffer. Examples: `basic_canvas.pas`, `classic_dots.pas`.
- **console-only** — no entry export; `write`/`writeln`/`read`/`readln`/`TextColor` programs via `wasmpascal_env` imports. Example: `hello_write.pas`.

The ABI is chosen automatically by peeking the compiled program's exports (`pascaldom_main` first, then `batchiness_main`, then the `wasm_init`/`wasm_update`/`wasm_get_pixels` trio, else console). Because that order would otherwise pick between two programs by accident, a `uses WEB` program that also exports another ABI's entry point is a **compile error** — drop the export, or drop `uses WEB`. `odin_env` provides the runtime hooks (write, trap, abort, `Math.*`, `rand_bytes`); `wasmpascal_env` is emitted only when the program uses console I/O.

**`uses WEB`** is an **embedded unit** — resolved from the compiler binary like `Crt` and `Classes`, with no `WEB.pas` on disk and nothing to register. It owns the `TWeb` facade, the callback dispatch table and the `pascaldom_invoke_callback` / `pascaldom_set_last_event` entry points. Reachability decides the imports, so a program that makes four bridge calls imports four entry points, not forty. String reads come in two shapes: `web.GetPropertyStr` / `StorageGetItem` / `EventKey` return a `String[255]` (one host call, no heap) and the `…Long` variants measure into a dynamic string of the exact length, so a long value is never silently cut.

**The `WEB` facade, in short:** `web.GetPropertyF64` / `GetPropertyInt` parse a numeric DOM property (`'100px'` → 100, clamped before `Trunc`); `EventClientX` / `EventClientY` / `EventKey` / `EventButton` / `EventTarget` read the current event; `MakeCanvas` / `RenderCanvas` keep the canvas and its context in `TWeb` fields (no `cv_h`/`ctx_h` globals); `WindowHandle` hands you `defaultView`; and string arguments anywhere in the bridge may be string *expressions*, not just literals — so `web.SetInnerText(h, 'score ' + n)` works directly.

**batchiness keyboard** — games self-wire their own keyboard via `batch_add_event_listener` on `document` (the bridge forwards the raw event and sets `batchiness_set_last_event` before the callback), then read `evt.key` / `evt.code` with `batch_get_property_str`. There is no host key mapping, so a game can use any key it wants. See `pong.pas` (and `pascaloids.pas`, `transforms.pas`) for the pattern: export `SetLastEvent name 'batchiness_set_last_event'`, wire `keydown`/`keyup` on `bGetGlobal('document')`, and in the callback map `evt.key` to your own key slots.
